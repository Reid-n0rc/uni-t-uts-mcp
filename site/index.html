natural-language.txt

Ask, don't type SCPI

"Center 100 MHz, 10 MHz span." The assistant picks the tools, sets the values and reads them back.

no-drivers.sys

No drivers needed

Raw SCPI over TCP port 5025. No VISA, no vendor software, just a network connection to the analyzer.

safety.dll

Safe by design

Resets, network changes, panel locks and file writes need an explicit confirm. Every setter reads the value back and warns when the instrument clamped it.

hardware.log

Verified on real hardware

Developed against a UNI-T UTS3036B (firmware V1.04.0040). Every quirk we found is written down.

errors.txt

Errors you can act on

Not connected, lost connection, timeout and instrument errors each get a clear message that names the command involved.

portable.js

Pure JavaScript

TypeScript on Node 22+, with just the MCP SDK and zod as dependencies and no native modules.

{{TOOL_COUNT}} tools, one tidy toolbox

This list is generated from the server's own tool definitions, so it is always current. Read-only tools are marked as such to the assistant; everything that changes the instrument goes through the safety checks.

Missing something? The raw SCPI tools are an escape hatch for any command in the programming guide. Full parameter docs live in the tools reference.

Built for real hardware

Every one of the {{TOOL_COUNT}} tools was tested against a real UNI-T UTS3036B running firmware V1.04.0040, the latest published. The server handles the analyzer's timing quirks so you do not have to. The details are in verified-hardware.md.

Sweeps that just finish

Start a single sweep and the tool returns when the trace is ready.

Behind the scenes: the analyzer ignores commands while it sweeps, so the server waits out the sweep time, then checks for completion with *OPC?.

Settings you can trust

Every setter reads the value back and tells you what the analyzer actually applied.

Behind the scenes: the analyzer quietly limits out-of-range values to the nearest valid one.

Errors that name the right command

Failures say which command caused them, even when the analyzer reports a problem late.

Behind the scenes: an unsupported query posts its error a few seconds later, so the connection filters those stale errors out.

Quick sequences stay safe

Commands are confirmed one at a time, so rapid-fire changes never confuse the analyzer.

Behind the scenes: lines sent back to back can produce phantom errors, so each command waits for an *OPC? reply.

Safe by default

Commands that reset the instrument, change its network settings or write files need your explicit confirmation.

Behind the scenes: they sit on a denylist and are refused unless the call sets confirm.

Built carefully

It drives real lab equipment, so the process is strict.

build.log

  • Test-driven: failing tests are committed before the code that fixes them
  • Every change is a pull request tied to an issue
  • A contract test runs every tool through the same failures: not connected, timeout, garbage reply, instrument error
  • A docs test fails if a tool is missing from the reference
  • CodeQL scans every pull request
  • Instrument settings are restored after every hardware test

Quick start

Works today with Node.js 22+ (or Docker), straight from npm and an analyzer reachable on your network. Use your analyzer's address in place of 192.168.1.100.

Claude Desktop: download the .mcpb and double-click

Available from the next release: v0.1.0 does not include the .mcpb file yet. Until then use the JSON configuration below, or build it with npm run build:mcpb from a clone.

Download uni-t-uts-mcp-<version>.mcpb from the GitHub release and double-click it. In the install dialog enter the analyzer address (optional: you can also say "connect to the analyzer at 192.168.1.100"), keep port 5025 and transport raw, and install. Claude Desktop already includes the Node.js it needs.

Claude Code

from npm (macOS / Linux)

claude mcp add uni-t-uts -e UTS_IP=192.168.1.100 -- npx -y uni-t-uts-mcp

from npm (Windows)

claude mcp add uni-t-uts -e UTS_IP=192.168.1.100 -- cmd /c npx -y uni-t-uts-mcp

Or from the release tarball (the same files as the npm package):

terminal (macOS / Linux)

claude mcp add uni-t-uts -e UTS_IP=192.168.1.100 -- npx -y https://github.com/Reid-n0rc/uni-t-uts-mcp/releases/download/v0.1.0/uni-t-uts-mcp-0.1.0.tgz

terminal (Windows)

claude mcp add uni-t-uts -e UTS_IP=192.168.1.100 -- cmd /c npx -y https://github.com/Reid-n0rc/uni-t-uts-mcp/releases/download/v0.1.0/uni-t-uts-mcp-0.1.0.tgz

Windows needs cmd /c because npx is a .cmd file. UTS_IP is optional: without it, tell the assistant "connect to the analyzer at 192.168.1.100".

Claude Desktop (JSON), Cursor, VS Code and others

mcp config (JSON, macOS / Linux)

{
  "mcpServers": {
    "uni-t-uts": {
      "command": "npx",
      "args": ["-y", "https://github.com/Reid-n0rc/uni-t-uts-mcp/releases/download/v0.1.0/uni-t-uts-mcp-0.1.0.tgz"],
      "env": { "UTS_IP": "192.168.1.100" }
    }
  }
}

mcp config (JSON, Windows)

{
  "mcpServers": {
    "uni-t-uts": {
      "command": "cmd",
      "args": ["/c", "npx", "-y", "https://github.com/Reid-n0rc/uni-t-uts-mcp/releases/download/v0.1.0/uni-t-uts-mcp-0.1.0.tgz"],
      "env": { "UTS_IP": "192.168.1.100" }
    }
  }
}

Other ways to install

from the git tag

npx -y github:Reid-n0rc/uni-t-uts-mcp#v0.1.0

Docker (amd64 and arm64)

docker run -i --rm -e UTS_IP=192.168.1.100 ghcr.io/reid-n0rc/uni-t-uts-mcp:0.1.0

from a clone (prints your exact config)

git clone https://github.com/Reid-n0rc/uni-t-uts-mcp.git
cd uni-t-uts-mcp
npm ci && npm run build
npm run client-config -- --host 192.168.1.100
